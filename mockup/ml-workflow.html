Deploy utility FR-10

  1. Load ml_pipeline/artifacts/model_bundle.joblib.
  2. Validate the bundle: fitted pipeline object present, feature spec lists all 67 features with group and key flags, metadata carries Failure-class metrics.
  3. Copy the validated bundle to models/model_bundle.joblib.
  4. Record the deployment timestamp and print a summary for the Software Developer.

Verify utility FR-11

  1. Load the deployed bundle and confirm it is loadable by the running scikit-learn version.
  2. Run FR-07 input validation against the feature spec on deliberately bad sample rows (missing field, out-of-range value).
  3. Run inference on sample rows covering both classes; check probabilities are in [0,1] and labels match class_labels.
  4. Print a pass/fail report. A failing report blocks the deployment from being trusted.

The accuracy trap

A trivial model that always predicts "No Failure" scores 93.08% accuracy while catching zero real failures. Random Forest looks strong on paper at 94.80% accuracy, yet it detects only 36.10% of real failures (Failure recall). Accuracy alone cannot tell these three models apart from the trivial baseline — this is why selection is driven by Failure-class precision, recall and F1, never accuracy (spec section 6.3).

Selection rationale

Plain Logistic Regression is deployed: it has the highest Failure-class F1 (0.7589) of all six candidates, meaning the best balance of precision and recall. The balanced variants trade too much precision for recall (LogReg-balanced catches 93.5% of failures but is wrong on almost half of its Failure predictions, precision 0.5373 — too many false alarms for a maintenance team to act on). Random Forest's recall (0.3610, or balanced: 0.2419) is too low to trust for a safety-relevant classifier regardless of its accuracy. Confusion matrix on the 4,000-row test set: TN 3,686 · FP 37 · FN 85 · TP 192.
