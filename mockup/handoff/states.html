States

Every data view needs more than its happy path. This page collects the loading, empty, blocked, invalid, missing and destructive states so none of them get designed in a hurry during implementation.

Loading

Shown while the deployed model runs inference, or while a table is being read from the local SQLite database.

Inline loading row
Validating inputs and running inference with the deployed model…
Skeleton content

Shown on: Run Classification (while inference runs), Battery Records / Classification History (while the table loads).

Empty (no records)

A collection view that genuinely has zero rows — different from Not-found below, which is a single record that cannot be located.

No battery records yet

No batteries have been added to the system. Create the first record to begin running classifications.

Shown on: Battery Records (no records), Classification History (no classifications), Classification History filtered to zero matches.

Awaiting repeat inspections

The measurement-trend panel needs at least two stored classifications for the same battery before a line means anything. With one reading there is a point, not a trend, and drawing a flat segment through a single value would imply a stability the data does not support. This is the state the panel shows until a second inspection exists — it is the normal state for a newly added battery, not an error.

Not enough readings yet

This battery has one recorded classification. Run a classification again after the next inspection and the trend for State of Health, Capacity Loss and temperature will appear here.

Trigger
COUNT(classifications) < 2 for the battery; one point is not a series
Not an error
uses the neutral empty-state panel (dashed border, muted icon), never the warning or failure palette
Exit
resolves on its own as soon as a second classification is stored; the call to action is the thing that creates one

No model deployed spec section 5, stage 2

Per the 3-stage workflow (spec 4.3), stage 2 — Model Deployment & Verification — must complete before stage 3 can classify anything. The system never fabricates a result; if models/model_bundle.joblib is missing or fails verification, classification is simply unavailable.

No model deployed yet

Classification is unavailable until a Software Developer deploys a validated model bundle (UC-04, FR-10) and it passes verification (UC-05, FR-11). Battery records can still be viewed and edited.

Shown on: Run Classification (replaces the entire form), Overview (the "Model deployed" chip switches to its warn tone — see Components → Status chip).

Validation error FR-07

Not found

A specific record that cannot be located — a stale link, a mistyped serial in the URL, or a deleted record. Distinct from Empty: the collection is not necessarily empty, this one lookup just failed.

No matching battery record

No record matches BAT-99999999. Check the serial number, or create a new battery record.

Shown on: Battery Records (search with zero matches, or a direct link to a record id that no longer exists), Run Classification (the pre-selected record from a deep link cannot be found).

Destructive-action confirmation

Shown before an irreversible action such as deleting a battery record. The dialog names the exact record and states the consequence in full sentences, never just "Are you sure?".

Shown on: Battery Records (record detail / row actions).
