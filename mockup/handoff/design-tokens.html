Design tokens

Every custom property defined in tokens.css, rendered as a live specimen. Contrast ratios below are computed with the WCAG 2.1 relative-luminance formula from each token's actual hex pair, not estimated — where a pair fails, that is stated plainly, including two places where it fails and tokens.css's own comment overstates the number (noted inline).

Finding: --c-text-muted on --c-surface-sunken fails AA (4.35:1)

tokens.css's own comment names --c-surface-sunken as the background for "table headers, inset wells, code blocks" and separately claims --c-text-muted is "still AA" — true only against --c-surface/--c-bg, not against --c-surface-sunken itself. Wherever muted text sits directly on a sunken surface (a unit label inside a code block, a caption inside an inset well), use --c-text-secondary instead — it clears 6.6:1 on that background. This handoff follows that rule throughout; the app screens should too.

Focus ring

Finding: --focus-ring alone measures ~1.79:1, below the 3:1 AA floor for focus indicators

--focus-ring: 0 0 0 3px rgba(29, 78, 216, 0.35) blended over white resolves to roughly #B0C1F1, which measures 1.79:1 against both --c-surface and --c-bg — under the WCAG 2.4.11 / 1.4.11 non-text 3:1 minimum for a focus indicator used alone. Every interactive element across this entire handoff section pairs it with a solid 2px solid var(--c-primary) outline (6.70:1, comfortably AA), which keeps the token's soft glow as a secondary cue while the hard outline carries the compliance. The production app should adopt the same pairing rather than the raw token alone.
