Feature attribution explainability

Answers "why this result" for a single prediction. The data's job here is polarity — which way each input pushed this one classification — so the form is a diverging bar chart around a neutral zero axis, never a single ranked ramp. The specimen below is the real decomposition for BAT-10000942.

How to compute it

No SHAP or LIME dependency is required or wanted. The deployed estimator is LogisticRegression, so the decomposition is exact:

z   = pipeline.named_steps["preprocessor"].transform(X_one_row)
w   = pipeline.named_steps["estimator"].coef_[0]
b   = pipeline.named_steps["estimator"].intercept_[0]

contribution_j = w[j] * z[0][j]          # per EXPANDED column
log_odds       = b + contribution.sum()  # reconstructs predict_proba exactly
probability    = 1 / (1 + exp(-log_odds))
Aggregation
one-hot columns are summed back onto the originating categorical feature, so a row in the chart is one model input — the thing the specialist actually typed — not a dummy variable
Rows shown
top 8 by absolute contribution; the summed remainder is reported in the footer so intercept + shown + remainder == log-odds visibly closes
Bar scale
each bar is scaled against the largest absolute contribution in that prediction, so the widest bar fills exactly half the track; scales are per-prediction, never global
Geometry
track height 22px; zero axis 1px var(--c-border-strong) at 50%; bar height 10px, top offset 6px, radius 4px on the outer end only
Grid
minmax(0, 11rem) / minmax(0, 1fr) / 4.5rem, gap var(--space-3); the two minmax(0, ...) are load-bearing — without them the label column's intrinsic width pushes the page sideways
Colour
var(--c-failure) for positive, var(--c-ok) for negative; never colour-alone — the signed value is printed and a legend is always present
Text
labels and values wear text tokens, never a series colour
Below 640px
collapses to 2 columns with the track spanning the full row, rather than crushing the plot area to a few pixels
Verification
reconstructed probability must equal the stored probability to within 1e-6; this is a usable unit test

Measurement trend (small multiples)

Condition over successive inspections. Capacity Loss, State of Health and temperature carry different units and scales, so they are three charts with one series each — never one chart with two y-axes, which would make unrelated lines look comparable. A single-series panel needs no legend: its title names the series.

Data source
classifications.input_snapshot_json for the battery, ordered by created_at; one point per stored classification
Layout
grid repeat(auto-fit, minmax(240px, 1fr)), gap var(--space-4); reflows to one column on a phone without a media query
Panel
1px var(--c-border), radius var(--radius-lg), padding var(--space-4), min-width 0
Plot
SVG viewBox 0 0 260 86, width 100% / height auto so it scales without overflowing; 2px line, round caps and joins
Markers
r=2.5 hollow for prior readings, r=4 filled for the most recent; every point carries an SVG <title> giving date and value on hover
Y domain
fixed sensible range per metric, not auto-fit to the data — an auto domain exaggerates trivial movement into a dramatic slope
Colour
var(--c-series-1) for the line. Deliberately NOT a status colour: the chart reports a measurement, and colouring it red/green would pass judgement the model has not made
Empty state
with fewer than 2 stored classifications there is no trend to draw; the panel shows its "awaiting repeat inspections" state instead of a one-point chart
