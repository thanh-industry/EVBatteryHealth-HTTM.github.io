Engineering handoff

Build this from the mockup

This section is the implementation-ready half of the deliverable. The app screens (linked above) show what the product looks like; these seven pages document precisely enough that a Software Developer can build the real Streamlit application without guessing a single pixel, color, spacing value or validation message.

What this section covers

Three sources feed every page here, and nothing else does:

  • mockup/css/tokens.css — the locked design-token file. Every colour, type size, spacing value, radius, shadow and layout constant used on these pages is read directly from it. Nothing here is a raw hex code or an off-scale pixel value.
  • prod_content.md — real output captured from the running production system: the deployed model's measured metrics, the 12 key features with real training-set medians/min/max, real per-group field counts, real battery serials and classifications, and all six trained model candidates.
  • 2 – Group5_ProjectSpec_v2.pdf — the project specification: FR-01 through FR-16, UC-01 through UC-09, the three-stage workflow, the system architecture, and the ML approach (section 6).

Where a number in this handoff differs from a number shown on the app screens, this handoff is the one backed by prod_content.md — see Traceability and this section's README for the specific deltas found during this pass.

How to use it

01 · Tokens first

Open Design Tokens next to tokens.css. Every swatch names its CSS variable, its hex, where to use it, and (for text/background pairs) its measured WCAG contrast ratio.

02 · Components, state by state

Components gives every interactive element's default, hover, focus, disabled and error states with exact padding/height/radius/colour tokens — read these as the literal CSS to write.

03 · Then layout, states, ML, coverage

Patterns for the shell and responsive rules, States for everything that isn't the happy path, ML Pipeline for the model story, and Traceability to check nothing in the spec was missed.

Contents

Design Tokens

Live colour chips (hex + variable + usage + contrast ratio), the full type scale at actual size, the 4px spacing scale drawn as measured bars, radii and elevation samples.

Components

Button, input, select, card, table, status chip, expander, modal, tabs, search field, pagination — and the Failure / No Failure result panel in full detail, every interaction state, redlined dimensions.

Patterns

The app shell and its 268px/1180px constants, responsive behaviour at 375/768/1024/1440, the two-step Run Classification flow, the 12-key + 9-group parameter pattern, table overflow, and the min-width: 0 rule.

States

Loading/skeleton, empty, no-model-deployed, validation error (real messages), not-found, and a destructive-action confirmation — with which screens show each one.

ML Pipeline

The 3-stage workflow, dataset facts (20,000 rows, 93.08%/6.92% split), the preprocessing pipeline, and all six candidates — with the accuracy-paradox insight shown visually, not just in prose.

Traceability

Every FR-01–16 and UC-01–09 mapped to the screen or component that satisfies it, with links into the exact page — what a grader checks against the spec.

Offline, by design

No network, no build step

This whole submission is opened by double-clicking a file. Fonts are self-hosted (../fonts/), there is no CDN link, no bundler, and no fetch() of local files (blocked on file://). Every diagram and chart on these pages is hand-authored inline SVG.
