UX states

Every data view in this application needs a loading, empty and error state, not just the "happy path" shown on the other pages. This page collects them in one place for review.

Shown while the deployed model runs inference, or while a table of records is being fetched from the local database.

Empty

Validation error

Shown when a parameter fails the model's feature specification (FR-07) — out of range, wrong type, or a required field left blank. Errors sit next to the field, never only in a banner.

No model deployed yet

Shown instead of the classification form when models/model_bundle.joblib is missing or fails verification. The system never invents a result (spec section 6 rule).

No model deployed yet

Classification is unavailable until a Software Developer deploys a validated model bundle (UC-04, FR-10) and it passes verification (UC-05, FR-11). Battery records can still be viewed and edited.

Confirmation dialog

Shown before an irreversible action, such as deleting a battery record. Click the button to open the dialog.
